# Interview intelligence and content pipeline

## Phase 8.5 architecture audit

The pipeline extends the Phase 4 editorial schema and the Phase 8 PostgreSQL-first runtime. The existing `sources`, `source_documents`, `source_document_versions`, `source_chunks`, `ingestion_records`, `ingestion_candidates`, `ingestion_review_events`, `question_versions`, `rubric_versions`, and pgvector tables already represent provenance, quarantine, editorial versions, audit history, scoring packets, and retrieval publication. The existing `interview_plans.setup_snapshot` and `plan_items.selection_reason` preserve planning inputs and selection reasons.

The base schema is not sufficient for this phase without an additive migration: reviewer IDs are not tied to authenticated accounts; voluntary experience requires a company label and does not persist explicit consent flags; source records do not represent adapter permission scope, retention, scheduling, and withdrawal metadata; and the adapter table only accepts local-file imports. Migration 009 adds those fields, plus a permission-basis/evidence hash and explicit scope for background operations, while keeping existing rows and migrations intact.

Durable operations and the transactional outbox are extended in migration 009 with explicit `source`, `submission`, `question`, and `maintenance` scopes. Content jobs have no fake session owner, use SQL as the durable authority, and travel through the existing BullMQ queue by stable operation ID. The worker leases and fences content results, retries typed transient failures, and rechecks source permission and withdrawal before execution and publication. Local-file collection reuses the bounded Phase 4 adapter and exact approved-byte hash contract. REST imports with explicit derived-data and model-processing permission enqueue a separate durable extraction operation; the result creates proposals, never approvals. Expiry reuses the current ingestion purge logic.

## Permission policy

Every source starts disabled. An enabled source needs an accountable human reviewer, an exact permission basis, evidence and its hash, terms revision, allowed scope, attribution rules, and explicit limits on storage and model processing. Content collection fails closed unless the source is enabled, permitted, approved, not withdrawn, and has the reviewed permission fields. A public URL or a permissive `robots.txt` file is not sufficient permission. The REST/RSS collectors are implemented, but no external source permission was independently verified for Aptlyra's use; no real third-party source is enabled or contacted.

## User submissions and quarantine

The authenticated submission flow requires practice-use consent and a right-to-share confirmation. It warns against confidential or personal information. Submissions are untrusted, screened, normalized, hashed, retained in quarantine for a bounded period, and excluded from retrieval and planning until editorial review and the existing publication gates succeed. Users can withdraw their own pending submission. Company names remain unverified self-reports and are never represented as official interview banks.

## Review and technical truth

An authenticated reviewer account must be explicitly linked to an enabled human reviewer record. Fixture reviewers are test-only. Interview experiences are signals about reported topics, not technical correctness sources. Technical references must be approved independently. A question can be content-approved while its rubric remains provisional; only a second human approval of the exact rubric packet can produce a reviewed rubric. Frozen Phase 7 weights are unchanged.

## Retrieval, planning, and withdrawal

Publication reuses question versions, retrieval entities, 384-dimensional pgvector embeddings, and the current retrieval service. Embedding failure must keep an item unavailable to retrieval. Planner policy must preserve competency coverage, difficulty and time constraints, and distinguish reviewed from provisional items. Withdrawal removes future eligibility while existing interview snapshots remain pinned. Trend labels require independent source and family counts; they must not imply official company questions or future guarantees.

## Phase 8.5B source collection and recent signals

Migration 010 adds collection interval/cursor/health state, permission-review hash, attribution flag and safe run history over the Phase 8 durable operation/outbox. Linked enabled human reviewers can register or edit sources, review the exact permission/config hash, enable/disable/withdraw sources, enqueue manual collection and inspect redacted history. Permission-relevant edits disable a source and clear its approval. No source is created as enabled.

The only network adapters are bounded REST/JSON and RSS/Atom. Each source pins HTTPS origin, hostname, exact allowed paths and query keys. DNS answers are checked and pinned per request; private, loopback, link-local and metadata IPs are blocked outside deterministic tests. Redirects are limited and revalidated, responses are capped at 1 MB/8 seconds, content types are checked, XML entities are rejected, pagination is capped at five pages/100 items, and request validators are persisted. Requests use an Aptlyra User-Agent and no account cookies or authentication. Scheduling runs from the existing SQL reconciliation loop at a minimum one-hour interval, and collection jobs remain recoverable from SQL if Redis loses deliveries. Daily retention expiry is also enqueued through the same durable runtime.

Collected content is normalized, screened, hashed, deduplicated by source item/content, retained only when full-text permission exists, and inserted into the existing quarantined/review-required document pipeline. Structured role/company/round/date metadata is used only when explicitly supplied by the source and stored only when derived-data permission allows it. AI extraction is enqueued only when model-processing permission is explicit and matching consent is stored on the imported record; candidate question approval, technical references, rubric approval and publication remain separate human gates. Withdrawal disables scheduling, fences stale work, redacts source text/chunks and removes the source from current retrieval/trend eligibility while leaving historical interview snapshots intact.

Trend views cover 30/90/180-day windows, count distinct content hashes and independent sources, count question families, use occurrence date when present and lower-confidence report date otherwise, and apply deterministic freshness decay. Company remains null without explicit source metadata. The labels are “Recently reported”, “Frequently reported recently” and “Emerging topic”; these are reports, not forecasts or official company question banks.

Recent trends are opt-in in planner setup and saved in the immutable setup snapshot. The planner excludes provisional content by default; when opted in, reviewed/scoring-ready questions sort first and provisional selection is capped at floor(30% of the effective question count). Coverage, family dedupe, role/company/date, mode, time and difficulty constraints still apply. Preview labels distinguish reviewed core from fresh/provisional signals.

## Operator procedure and remaining integration

The reviewer console now exposes submission extraction (only with explicit AI consent), exact-hash question approval/edit/reject/duplicate/withdraw/publish, technical-reference attachment/removal, rubric draft/edit/approve/reject/withdraw, scoring queues, published questions, and seed review. Structured AI proposals are bounded and versioned; server-side checks validate metadata, taxonomy, classification, confidence, and exact source evidence spans. AI proposals remain in review-required state and cannot approve themselves. The publication readiness view distinguishes reviewed/scoring-ready, fresh/provisional, and approved-not-retrieval-ready; publication reuses the existing Phase 5 embedding generation and does not activate an item when embedding fails. Technical reference rows pin source-version and permission hashes, and loss of reference eligibility removes future reviewed/scoring-ready status.

Phase 8.5A's content-to-reference-to-rubric-to-embedding retrieval path is verified with a disposable deterministic E2E fixture. Phase 8.5B's disposable schema, persistence, source collection/extraction, planner, runtime, smoke, collector and regression suites pass. A single source-to-interview-to-report E2E and the full trend, source-recovery and withdrawal matrix remain incomplete. No real source permission was independently verified, no third-party source was enabled, and no live account review or seed approval was fabricated. Phase 9 has not started.
